# corpus/QUALITY.md — the admission bar

An entry is admitted into `corpus/knowledge/` only when it clears all of:

1. **Provenance** — every factual claim carries a cited, checkable source
   (author + year, standard edition, or stable ID). A claim the author
   cannot verify is marked `(to-verify)` inline — never laundered into
   assertion. Invented sources are a conformance defect, not a style issue.
2. **Calibration** — every framework entry names its status: mainstream /
   contested / discredited, with the reason. Pop-mythography
   (Campbell-as-universal, strong Whorf, glottochronology, Frazerian
   evolutionism) must be flagged as such on first use.
3. **Coupling** — the `- couples:` line names the systems/files the entry
   connects. An entry that couples nothing is reference, not craft; it must
   say so.
4. **Usability** — a worldbuilder can act on it: decision tables, typology
   tables, checklists, worked examples. No essays.
5. **Canon hygiene** — no entry decides what is true in any world. Canon
   recording and consistency verification belong to lore-shokunin; entries
   end at the handoff.

Rejections are kept with their rejection reason (see `lessons/`) — a
rejection is evidence of taste.

Source tiers (A/B/C, each scoped to a claim) are defined in `SOURCES.md`,
the lane's opened source registry; a tier-C row is a lead, never sole
support for an admitted claim.

6. **Source authority stays claim-scoped** — publisher descriptions and abstracts are tier B for substantive claims about a work, even when accurate; reserve tier A for sources primary or authoritative for the exact scope. Correct a filed tier with a superseding SOURCES row, never an in-place tier edit. Grounded in the reviewer disagreement and correction at `corpus/lessons/round-49.md#post-review-corrections` (S034, S038, S039 → S044–S046).

7. **Claims stay separable** — each round claim verifies on the base commit plus only the paths it lands itself. Its added lines may not cite an identifier another claim newly exports, nor name a path another claim newly lands; a counterfactual leg that quietly keeps the dependency (inline URLs standing in for the registry rows) or rewrites the other claim's bytes before checking does not count as verification. Sources a claim cites are that claim's lands. Run `tools/check-claim-separability.py` on the round manifest before dispatch. Grounded in the round-49 REJECTED-HONEST-STOP at `corpus/lessons/round-49-verifier-spotcheck.md#adjudication` (C cited the registry S created). A claim's declared exports name the exact id block it owns before dispatch — the ids it creates, or a block reserved to it that no other unit assigns and whose unused ids stay unassigned — never an open range: loop S000-S999 against each export and the matched set must equal the declared block. Grounded in the round-55 closure's routed defect 1 (`corpus/lessons/round-55-verifier-spotcheck.md#5-routed-defects-lane-fixes-next-round`, R55-M5: an S285-S999 export matched O's fixture id S900 and the declared check exited 1) and shown able to fail by `.ufo/waves/round-56/build/CriticSeparabilityExports.md` §1-§2 (the round-55 manifest exits 1, the exact range exits 0; a round-56 tool line naming S360 yields an O->C finding while S358 and S419 do not).

8. **Declared inputs run before dispatch** — every declared counting or acceptance command runs once on its exact declared input before the round dispatches, and the receipt is committed with the declaration. An input-shape error (missing manifest keys, an unreadable file, unrecognized arguments) fails the declaration, not the round: correct the declared command or input and re-run before dispatch; never substitute a different input after measuring. A not-yet-landed path is the only expected error before landing. A closure checks this from committed bytes: each command in the dry-run receipt matches its declaration verbatim and exits 0 or stops only at an absent land. Grounded in the round-50 Decision at `corpus/lessons/round-50-verifier-spotcheck.md#decision` (Ca's frozen leg on `reports/round-50/claims.json` exited 2, `SEPARABILITY_INPUT_ERROR manifest is missing base, schema`) and mistake R51-M1 at `corpus/lessons/round-51.md#mistakes`.

9. **Dry runs are checked both ways** — supersedes criterion 8. Every declared counting, acceptance and separability command must appear in the pre-dispatch receipt, and every receipt command must match a declaration verbatim. Expected pre-landing results are named in the receipt: an absent land (exit 2, the land named), or an after-value comparison failing with the before value printed. A checker that stops at its first absent land leaves its later legs unevaluated, and the receipt says so. 11. **Each claim clause is shown able to fail** — adds to criterion 9, which checks that the receipt and the declaration agree; this criterion checks that the declared commands can fail at all. The declaration lists each claim's clauses (a count, a path, a form such as `path:line`, an index row, a status, a `used-by` cell, "one new entry"), and a non-author seat checks the list against the statement's words before dispatch. A clause no command checks mechanically (a topic, "on X as method", what a source carries) is listed as review-only and is never covered by a weaker stand-in predicate such as a `- topic:` pattern. Each other clause names the declared counting or acceptance command that checks it, and that command reads the exit status of every tool it runs: no pipe without `set -o pipefail`, and no `$(…)` or `|| true` that hides a status. Controls run the declared argv verbatim from the root of a scratch copy. A green control is a copy where every clause holds, and there the command exits 0; a stand-in landing is allowed in the copy only and is never landed. A red control is one per mechanical clause: it changes that clause alone with the nearest near-miss, not an easy break (a `dir/` token for a `path:line` clause, not a missing file; a second added file with an existing one removed, so the count still holds), and the command exits non-zero, printing that clause's leg as failing and every other leg as passing. The base run does not count as a control: there every clause is false at once. Where the statement ranges over rows that exist at base, the before-value matches the predicate applied by hand to those rows. Check from committed bytes, before dispatch: the clause list in the declaration, the control script that builds each copy, its receipt in a file criterion 9's two-way check does not read (no `$ ` prefix), and the sha256 of each instrument it ran; a closure replays a sample. A clause with no control is unverified, not passing. Shown able to fail (receipt `reports/round-53/telemetry/criterion11-controls.txt`, made by `reports/round-53/criterion11-controls.sh`): round 51's D argv exits 0 with one anchor replaced by `linguistics/`, and round 52's C argv exits 0 with the index row removed (the sweep exits 1). Round 53 does not meet this criterion: its declaration `60f1d2a` carries only the all-false base run, its per-clause controls ran in the build wave and after landing, and its after-landing receipt has no control for C's S187 floor or `mined` status or for D's SID_BAD. It binds from round 54's declaration. Grounded in mistakes R52-M3 and R53-M2 (`corpus/lessons/round-52.md#mistakes`, `corpus/lessons/round-53.md#mistakes`): round 51's D counter and round 52's C acceptance could not fail on a clause their statements made, and in round 53 the build-wave critic found two C clauses `accept-c.py` does not check (`.ufo/waves/round-53/build/CriticClaimSizingC.md:12-13`). 19. **Receipts run at the revision they stamp, and carrier-parentage is post-records** — adds to criterion 17, which pins the revision the read-path bytes equalled; this criterion pins where the run happens, how the receipt proves it, and which legs can only exist after the records commit. Before data, every round counter takes a required lands revision (`--lands <40hex>`) and never grades whatever worktree it happens to sit in: the evaluation runs at that revision — inside a clone materialized at it, or over committed bytes read from it (`git show <lands>:<path>`) — and the receipt proves stamp and evaluation agree, carrying `# stamped revision:`, `# evaluated revision:`, `# measured revision (lane main):`, `# tree:` and `# counter sha256 (self):` with stamped == evaluated == measured and the tree equal to `git rev-parse <stamped>^{tree}`. A run whose evaluated revision differs from its stamp prints FAIL and is not a receipt; a receipt that does not exist at the lands revision is a FAIL (`unreadable`), never a skip; a receipt carrying no stamped/evaluated headers is `missing_headers`, not retroactively gradable, and a pre-protocol receipt is re-derived by hand from `git log -1 --format=%H main -- <receipt>` and `git rev-parse <carrier>^` — no header is ever written onto its original bytes. Where a round's claims land in separate commits, each receipt stamps its own claim's lands commit: an earlier claim's receipt is never re-run at a later tip to cover it, and rows a later commit adds are never graded by it (criterion 7's separability, applied to receipts). Carrier-parentage — the commit that carries a receipt has the stamped revision as its parent — cannot be a lands-time leg, because at the lands revision its own carrier does not exist yet: it is post-records evidence, graded after the records commit with `--topo`, committed as its own telemetry file, and cited by no frozen predicate (a lands-time carrier leg can only print FAIL). Limits, stated: `--topo` needs a stamped header, so a pre-protocol receipt answers `no_stamp_header`; the counter-sha leg runs only for a receipt paired with its counter and is skipped — not failed — when the `# counter sha256 (self):` line is absent (criterion 17's pin and the round's accept-ca RECEIPTS leg carry that leg); and in `--lands` mode the paired counter is resolved from the worktree with `main` as fallback, so a counter edited after lands fails the sha leg instead of passing. 22. **A wall, CAPTCHA or HTTP-refusal record binds each User-Agent to the response that request got** — adds to criteria 10, 12, 13 and 21, restating criterion 21's field (3).
Scope: any Gate record whose reason cell opens with `wall:`, `captcha:` or `status:`; the record is one physical line, so a line-oriented check binds it.
Each request in the record is `UA "<exact string>" -> HTTP <code>, <bytes> B, wall present ("<marker>")|wall absent`, in that order: a User-Agent with no response of its own is not a record, an alias (`UA-B`) or an elided string (`Mozilla/5.0 …Firefox/131.0`) is not a record, and the literal string a re-opener would send is in the record itself.
The status decides nothing — the wall and the content both answer HTTP 200 (round-72 UNESCO 43,419 B wall vs 154,144 B narrative; round-73 Springer 200/3,038 B `<title>Client Challenge</title>`) — so the bytes and the marker are recorded per request and the reason names the one it rests on.
The second request is `Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0 Safari/537.36`, and the record says so when it was not made: a wall seen under one UA is UA-unknown, not a source property; a wall persisting under both is a valid reject; a wall present under the plain UA and absent under the browser UA voids the reject and the source is re-opened by ordinary means (round-72: 5/5 wall plain, 5/5 clean browser, full page under an empty UA).
The record carries `automation: none` or names the tool it used; a record naming browser automation, a solved CAPTCHA or a bypassed block is VOID under criterion 10 whatever its status lines say (a headless-browser UA is browser-shaped, so the shape check alone passes it). A 429 records its attempts and gaps per criterion 16 and is never read as UA-gating.
Check (red-before, pre-dispatch): over the round's `## Gate` section `grep -Ec "$GROUND"` must equal `grep -Ec "$SHAPE"` — GROUND `^[|*-].*\| *(wall|captcha|status):`, SHAPE `UA "[^"…]{8,}" -> HTTP [1-5][0-9]{2}, [0-9]+ B, wall (present|absent)` twice on the line — with `automation: none` in every in-scope record, and the three controls (missing, compliant, automation) filed with the run. Review-only, criterion 11: that the named observable is the one the reason rests on, and that a difference between the two responses shows up in the verdict.
Limits, stated: grep cannot tell a pasted UA from a sent one, cannot resolve an alias and cannot read a wrapped record; the verbatim output block and the re-open command in the record are what a re-opener repeats. Binds from round 73; no earlier Gate line is retro-fitted.
