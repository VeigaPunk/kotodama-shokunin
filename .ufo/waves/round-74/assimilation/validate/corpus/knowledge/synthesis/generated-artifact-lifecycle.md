## 1. What this workflow licenses

- A **file-ownership map and a rebuild loop**, not a generator. It tells a designer which files they may edit and what to do when a generated file is wrong.
- The split is load-bearing for evidence: an authored byte can be reviewed as a design statement; a generated byte can only be verified as a tool's output from its sources.
- A generated artifact is **build output**, so its evidence is a digest plus a revision, never its content read alone.

## 2. The source/generated split

| class | files (D4 example) | edited by | verified by |
|---|---|---|---|
| authored source | `components/01-brief.yml` … `12-provenance.yml` | the design seats | authored-source review; never regenerated |
| generated packet | `packet.d4.yml` | `tools/assemble-culture-d4.py` | `--check` byte-identity; `d4-assembly-check-gate`; frozen row |
| generated projection | `typed-labels.d4.yml` | `tools/d2-typed-labels.py` | `--emit` + `cmp`; `--check`; `d4-typed-labels-check-gate`; frozen row |
| derived record | `expected-holds.json` | derived from the projector's own output | `packet_sha256` / `projection_sha256` pins; equality checks |
| authored record | `ASSEMBLY.md`, `brief.md` | the integrator/scribe | read as a receipt; it records the chain, it is not the chain |

- Rule: if a file is generated, its **only** legitimate change path is a source
  edit followed by a rebuild. Hand-editing a generated file makes it stop being
  that tool's output and silently breaks every pin built on it.
- Rule: a generated file carries its generator's identity in the record
  (`examples/culture-d4/expected-holds.json` carries `projector_sha256`), so a
  reader can tell which tool produced the bytes.

## 3. The rebuild loop

| step | action | check |
|---|---|---|
| R1 edit source | change the authored component, not the output | the component's own review |
| R2 rebuild | run the generator (`assemble-culture-d4.py`) | the generator writes exactly one artifact |
| R3 drift check | run the tool's `--check` mode | byte-identity against the committed artifact, exit 0/1 |
| R4 gates | run the packet's gates over the rebuilt artifact | gate verdicts, exit 0/1/2 |
| R5 re-freeze | if the artifact is a frozen row's input, record a **new** row | never edit the recorded row in place |
| R6 handoff note | state which bytes are authored and which generated | the reader knows what a digest covers |

- Steps R2–R4 are the loop `examples/culture-d4/ASSEMBLY.md` §1 states in one
  sentence: “after any component edit, rebuild and re-run `--check` plus the gates”.
- A rebuild that changes bytes is expected when a source changed; a rebuild that
  changes bytes when **no** source changed is a finding (the generator is not
  deterministic, or the artifact was hand-edited).

## 4. What the lifecycle never licenses

- **A hand-edit is not a fix.** It is a defect even when the content looks right; the correct move is R1–R2.
- **A generated artifact is not a design statement.** Read as evidence, it is “this tool produced these bytes from these sources”, not “the designer chose this”.
- **A rebuild is not a review.** Determinism says the generator repeats; it says nothing about whether the output satisfies the gates or the declared hold set.
- **A digest is not truth.** It proves the bytes, never their soundness (Thompson; `../verification/gate-frozen-run-standard.md` §10).

## 5. Reviewer checklist

1. Classify every file as authored source, generated output, or derived record before reviewing.
2. For a generated file, confirm it is the tool's output: run `--check`; do not review the bytes as if authored.
3. After any source edit, confirm the rebuild and the `--check`/gate re-runs happened (R2–R4).
4. Confirm a changed artifact produced a **new** frozen row, not an edited one (R5).
5. Confirm the handoff note distinguishes authored from generated bytes (R6).

## 6. Decision record — the lifecycle rules this workflow adopts

1. **Adopted:** generated artifacts are never hand-edited; every change goes through the source and the rebuild loop R1–R4 (§2–§3; `examples/culture-d4/ASSEMBLY.md` §1). Consequence: a hand-edited artifact is a defect even when its content is right.
2. **Adopted:** every generated artifact names its generator, and the generator's digest is part of the artifact's record (§2). Consequence: a reader can tell which tool produced the bytes and when the tool moved.
3. **Adopted:** a source change is followed by rebuild + `--check` + gates; a byte change with no source change is a finding (§3). Consequence: non-determinism and hand-edits surface as the same class and are separated by the source digest.
4. **Adopted:** re-freezing a changed artifact records a **new** row, never an in-place edit (`tools/gates/frozen/round-18/README.md`). Consequence: the frozen history is append-only.
5. **Rejected:** treating a rebuild as a review or a digest as truth. Reason: both assert only that the tool repeated, not that the output is sound (§4).
6. **Open (to-verify):** whether the derived record (`expected-holds.json`) should carry its own generator identity separately from the projector's, since it is derived from a projection rather than produced by the projector directly. Owner: this lane's D axis; not disposed here.
