# CritLedgerDesign — Ca ledger attack (round 76)

## Verdict

The round-75 checker is materially stronger than a bare list of ids: `LEDGER` validates frozen ledger provenance, statement text at the base, observe-command shape, token parsing, and unique ids; `BASEMISMATCH` requires every measured pair to be red at base; `REPAIR` checks the parsed after-token against the observation and expected token; `ANNOTATE`/`NOSTUB` require an id-leading row with old/new tokens and a re-derivation command. But it does **not** establish that an accepted observer measures the stated subject, and its REPAIR after-statement check is independently editable and can be detached from the original statement. These are fixable design defects, not reasons to reject the entire Ca approach. Freeze a narrow, auditable observer grammar and bind each repair to the exact changed statement site; require annotations' expected token to match re-derivation.

## Strongest counterexamples (reproduced against a scratch fixture)

The following checks imported the round-75 `accept-ca.py` without modifying it; fixture root was `/fast/scratch/hyaku/kotodama-r76/CritLedgerDesign/fx` and the imported code's `observe_problem`, `leg_repair`, `leg_annotate`, and `leg_nostub` were called directly.

* A constant printer passes the observer guard: `git for-each-ref --format=808 --count=1` → `808\n`; `git ls-tree --format=808 <base> -- SHONEN.md` → `808\n`; `git log -1 --pretty=tformat:817 <base>` → `817\n`. In each case `observe_problem(argv, clone)` returned no refusal, and `parse_observed` extracted the supplied constant. Command: `python3 -B p1.py` in the scratch directory. Raw output: `for-each-ref ... ACCEPTED out='808\\n' parsed='808'`; `ls-tree ... ACCEPTED out='808\\n' parsed='808'`; `log ... ACCEPTED out='817\\n' parsed='817'`. `git rev-list --count <base>` also passed and returned `380`, which is real repository data but could be an unrelated subject. `LEDGER`'s “read-only git subcommand” allowlist does not constrain subcommand options/formatters. The existing constant-printer defense only blocks interpreter/echo-style binaries (`observe_problem`, `accept-ca.py:1112-1140`), not Git format channels.
* Reading the stated file is not prohibited. `LEDGER` proves `stated_text` exists at `stated_at` in base and that observe operands resolve in the clone (`leg_ledger`, lines 1409-1457); it never binds the observer's path/pattern to the claim's subject. `BASEMISMATCH` only checks parsed stated-token != parsed observation (`leg_basemismatch`, 1523-1558). Thus same-line self-reading that returns the stated token is caught as green, but a command reading an unrelated number from that same lesson can manufacture a red pair. Require observation to come from a declared ground-data path/scope independent of the statement text, and reject patterns that match the cited statement line. Do not treat mere “different token” as proof of a false claim.
* REPAIR is satisfied while the old claim remains: fixture base line was `(412 rows after round 56 — 367 mined)` and `statement_after` parsed `Registry rows: (\d+)`. Landing kept the stale base line and appended `Registry rows: 8`; `leg_repair` returned `green=['P1'] red=[]`. It also passed when the stale line was deleted and the matching statement moved to `NEW.md`, and when the match was an HTML comment. Command: `python3 -B p2.py`; raw output: `A-stale-retained -> green=['P1'] red=[]`, `B-deleted-relocated -> green=['P1'] red=[]`, `D-moved-to-comment -> green=['P1'] red=[]`. Cause: the after-path/regex is free-form (`statement_after`); the “base text still present” test only recognizes it inside a regex hit, and only on the declared after-path (`leg_repair`, 1596-1635). APPENDONLY explicitly exempts removals at a REPAIR `stated_at` line (1812-1903), so it does not rescue this. Require `statement_after.path` to equal the original statement path, the original stated text to be absent/replaced there, and the replacement token to be parsed from the changed hunk at the corresponding statement site—not an appended/comment/elsewhere decoy. If deletion is intentionally acceptable, make it an explicit disposition with a separate acceptance predicate rather than calling it REPAIR.
* A bare id is **already rejected**, so retain the existing guard rather than claim it is missing. In the fixture `ANNOTATE` and `NOSTUB` both require a leading id, old token, new token, and rederive string (`leg_annotate` 1741-1765; `leg_nostub` 2033-2062); current output for an id-only row was failure. However, a mechanically filled row passed even with `expected_after='1234'` while the actual observed lands token was `37`: `python3 -B p3.py` → `honest leg_annotate True ...`, `honest leg_nostub True ...`, `expected_after in pair: 1234 observed lands: 37`. `ANNOTATE` never compares `expected_after` with `obs` (1731-1765); require that equality and require the rederived command to be the frozen observer (or a separately declared, semantically equivalent observer). A row with the fields is not by itself evidence that the correction actually states a meaningful explanation; the present predicate is intentionally only minimum shape.

## Minimal guards and round-75 leg coverage

| Attack / guard needed | Round-75 coverage already present | Residual / smallest safe correction |
|---|---|---|
| Constant or unrelated observer | `LEDGER`: argv-only, allowlisted binaries/subcommands, no shell, no interpreters/echo; pinned revisions and operands constrained. `BASEMISMATCH`: red-at-base and no green pair. | Missing Git option grammar: `for-each-ref --format`, `ls-tree --format`, `log --pretty` print literals; `rev-list --count` may measure irrelevant state. Ban high-risk Git subcommands and allow only per-subcommand options/forms; reject format/template fields and require an explicit, frozen subject/path contract. |
| Observer reads its own lesson / claim text | `LEDGER`: statement text anchored in base; observe paths resolve there. `BASEMISMATCH`: exact self-read token generally becomes green. | No independence/subject-binding check. Disallow statement-file observation for a pair unless a declared structured data region is demonstrably separate; test observer pattern against the cited line and require source path/predicate to identify the same subject. |
| Statement token derived from lesson that is later edited | `LEDGER` reads the statement and token at immutable `base`; freeze/landings are pinned by the broader counter. | Base anchoring proves only what the base lesson said, not that it was the original filed claim or independently true. Freeze ledger before data and preserve a source-site digest/line binding; do not derive the claim's asserted token from a mutable post-data copy. For round-76, the chosen base is `98c486…`; pair sources must be demonstrably present there. |
| Delete stale statement and satisfy via a different statement | `REPAIR`: requires a parseable after token; requires token == observed == expected; attempts to detect old text. `APPENDONLY`: protects removals generally. | After path is caller-selected; allowed `REPAIR` line deletion exemption; stale detection is regex-hit-dependent. Require exact site/hunk correspondence, same path, and replacement of old line. |
| ANNOTATE row contains only pair id | `ANNOTATE` requires row-leading id plus old/new token and executable rederive; `NOSTUB` independently checks same minimum shape and placeholder tokens. | This is already covered (bare-id counterexample fails). Still require `expected_after == observed`, and make row's correction evidence/command precisely tied to frozen pair. |

One additional weak binding: `stated_parse` is evaluated against the ledger's `stated_text` (`stated_token`, 1251-1264), then checked to occur in that text; it is not parsed from the immutable source line itself. `LEDGER` separately checks `stated_text` occurs on that base line, so changing only the source line cannot silently alter the captured fragment, but a cherry-picked fragment can still change the meaning/context. Require the statement span to be the complete claim clause (or a frozen explicit span), not an arbitrary substring.

## F1–F13 and verifier §7: retain only measurable tokens

A ledger pair must be one independently re-derived, typed token—not a narrative verdict, set-valued explanation, or inference requiring a human to interpret surrounding prose. Where a number is countable, bind it to the precise committed artifact and command. From the sweep, countable candidates are F5 (three byte-size statements, each a separate pair), F8 (whole-document count), numeric subfacts of F9 (S888 `chars` and `before`, S892 `before`; **drop S892 `chars=4097` because it is true**), F10's specific S885/S887 byte counts, and F11's byte count. F13's “line ends in `%`” can be a count of matching lines only if the statement is narrowed to that exact predicate and the command is pinned; otherwise drop its prose diagnosis.

## Recommendation for round 76

Keep >=10 genuinely distinct, base-red, scalar pairs, but do not reach the threshold by splitting one narrative defect into arbitrary fragments. Use immutable evidence files / fixed registry facts as observation sources; pin every repository operand to the base; reject printer formats and observers whose pattern matches the stated source. For REPAIR, require a real changed replacement at the original path and hunk. For ANNOTATE, keep leading-id + old/new + executable rederive checks, add `expected_after == observed`, and require a structured row field binding the rederive result to the source claim. The staged/landed artifact identity is essential: e.g. F5 observations must be the named lane paths, not similarly named source copies.
