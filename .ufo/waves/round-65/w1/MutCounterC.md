## Method (identical for original and mutant)

`stage/mut-c/harness.py` loads the named counter by path and patches only
`subprocess.run`, answering the counter's three git calls from fixture files
(`git show BASE:corpus/SOURCES.md`, `git show BASE:reports/round-61/reopen-quote.py`,
`git diff --name-only …`); every other subprocess (locator / sweep / cited-lines) runs for
real. No repository is created; no write outside the stage tree; **no live re-open was
performed** — the real `reports/round-61/reopen-quote.py` was never executed, the fixture
locator is a stub with the real leg's contract (first line `LOCATED…` + exit 0 on success).

Seven minimal fixture roots were generated by `stage/mut-c/build_fixtures.py`: `clean`
(honest landed tree: 675 real base rows + 26 appended rows, 26 cited bullets),
`m1`/`m3`/`m4`/`m5`/`m6` (one shortcut each), `red` (the unlanded dry-run state: entry absent,
no new rows, no README topic row). Base registry bytes are the real
`17c32302:corpus/SOURCES.md` (`base-sources.md`, sha256
`b92b95818b94dc80996eae6fafe55344f86fac04b02c894f29f895afff25c5cf`, 675 rows).
All run output is committed under `stage/mut-c/out/` (one file per run, `<script>-<fixture>`).

Baseline sanity: original `PASS` on `clean` (10/10 legs) and `FAIL` on `red` (8 legs fail),
so every difference below is attributable to the mutated bytes.

## Findings from the attack (counter-hardening evidence, not contract changes)

- **F1 — the frozen instrument was not frozen during the wave.** Four byte revisions in one
  seat window (`deefbe58…` → `8f44b649…` → `ad5540…` → `bc35de5…`). The frozen dry-run
  receipt `reports/round-65/telemetry/dry-run-c.txt` was produced against rev 1: it has no
  `# counter sha256 (self):` header and prints `RESTATE PASS bad=[] lines=0`, a line the
  current revision cannot print (it prints `RESTATE FAIL bad=[] lines=0/26`). **The receipt
  does not evidence the predicate over the bytes on disk.** Re-run the dry-run after the
  freeze and re-file the receipt.
- **F2 — no receipt pins the counter's bytes.** The `# counter sha256 (self)` line (added in
  the 460-line revision) is the only self-identification, and neither receipt carries it.
  Every mutant in this table changes that printed digest; a receipt that records it would
  make an edited counter detectable by inspection. As filed, editing the counter leaves the
  telemetry indistinguishable.
- **F3 — the dry-run discriminates almost nothing.** On the red input, m1/m2/m3/m5 produce
  leg output byte-identical to the original (verdict FAIL either way); m4 and m6 differ in
  exactly one leg line (`ONEID PASS`; the 3-id `LIVE` subset) while the printed verdict stays
  FAIL. A receipt read as a verdict kills none of the six; only a line-by-line diff of the
  leg log kills m4 and m6.
- **F4 — APPEND's literal `26` is now redundant.** ROWS already requires 26 distinct rows and
  rev 3's base seeding rejects any new id pre-existing in the base, so `base+25` is
  unreachable; the mutant survives only as a false-reject. No coverage action needed beyond
  this record.
- **F5 — LIVE is a fixed sample.** Six of 26 rows; a 3-row sample still passes. Users of the
  receipt should read LIVE as a spot check, not as 26-row evidence; if row-level coverage is
  wanted, the subset should be derived (e.g. per-row first/last) rather than fixed, or each
  row's locator result recorded by the row seat.
- **F6 — the rev-1 forcing control is not in the lane.** `controls-c.txt` control 2 ran
  `--root /tmp/k65-ctl`, a scratch repo outside `.ufo/waves/round-65/` (still present on this
  host at probe time, 829-line registry, and source hosts of the form
  `ctl-*.example.org`, which the HOSTS placeholder tuple rejects — [INFERENCE] from the row
  text plus the HOSTS tuple; that run was not completed, so the HOSTS failure is not observed).
  Its receipt shows 6 of 10 leg lines (no ONEID/HOSTS/SWEEP/LIVE), so it is
  neither reproducible from lane bytes nor a full run of the frozen counter. The near-copy
  control is supplied by `fixtures/m1` here instead.
- **F7 — harness limits.** Fixture locator / sweep / cited-lines are stubs with modeled
  semantics; `TZ`-free, network-free. Absolute PASS on a fixture is not evidence about the
  real locator, only that the leg logic discriminates. Fixtures are synthetic
  (`fixtureN.test`, synthetic clauses) and say nothing about real restatement quality.
