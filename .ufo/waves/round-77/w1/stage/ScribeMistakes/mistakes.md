## QUALITY criterion or checklist line? (the in-place-report-rewrite class)

**Decision: checklist line, not a QUALITY criterion.** Reasons, each with its measurement:

1. `corpus/QUALITY.md` is the admission bar for corpus artifacts. It holds 29 numbered criteria
   (`grep -c -E '^[0-9]{1,2}\. \*\*' corpus/QUALITY.md` → `29`, highest `29. **`), each gating an
   entry, a registry row, a receipt, a ledger or a counter; none names the lane report —
   `grep -c -i 'lane report' corpus/QUALITY.md` → `0`. The one
   `grep -n -i -E 'filed report|erratum|report-correction' corpus/QUALITY.md` hit is line `141`, and
   it is a substring inside the fixture cell `MISFILED reports/round-74/evidence/S883.txt` — a receipt
   example, not a criterion about reports.
2. The obligation already exists elsewhere and is a *record* rule, not an admission rule:
   `/home/vgpnk/Projects/shokunin/PROTOCOL.md:134-137` — "a correction to it lands in the correcting
   round's own report, or as an erratum appended after the filed bytes in a new commit and naming the
   text it supersedes — never a rewrite of the filed bytes, labelled or silent."
3. The round-77 QUALITY slot is already spoken for: no `^30.` criterion exists at base
   (`grep -c '^30\.' corpus/QUALITY.md` → `0`) and seat `ScribeQuality30` is drafting criterion 30 as
   "ledger pairs execute". A second criterion this round would collide with that draft.

**Proposed checklist line** (to be installed by the L1 — the fleet prompt and `LOG.md` are outside this
seat's write scope; suggested homes: round-prompt §4 *Report contract* as a final bullet, and the
`LOG.md` `## Round 77` conformance bullets):

> **Filed reports are append-only.** A correction to a filed round report lands as (a) an entry in the
> correcting round's report, or (b) an erratum appended after the filed bytes in its own commit, naming
> the text it supersedes. Never rewrite the filed bytes. Check: `git -C <fleet-root> log --format='%h %s'
> -- .ufo/reports/round-<N>/<lane>.md` lists one filing commit per attempt; every later commit touching
> that file must print `0` deletions in `git -C <fleet-root> show --numstat <commit> --
> .ufo/reports/round-<N>/<lane>.md`. A post-filing commit with a nonzero deletion count is an in-place
> rewrite and a conformance defect.

The check is one command over committed bytes, so the closure seat can run it without judgement. It is
deliberately *not* a `## Mistakes` fix shown able to fail by a counter: no counter reads the fleet repo,
and inventing one for a record clause is the over-mechanisation QUALITY 20 warns about.
