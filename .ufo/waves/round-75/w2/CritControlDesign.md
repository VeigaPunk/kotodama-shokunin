# CritControlDesign — round 75 controls / bypass review

Scope: claims and control implementation as currently staged in the lane; no edits to claims, ledger, counters, or controls. `w2/parts/` is empty and `w2/stage/` contains no claim landing, so conclusions about assembled legs below are from the final claim wording and committed counter/fixture text, not executions against assembled parts.

## Findings

1. **`run-controls.sh`'s ordinary control path is telemetry-confined, but does not itself produce every promised artifact.** It `cd`s to the lane, creates `reports/round-75/telemetry`, and redirects both counter outputs to `controls-c.txt`/`controls-ca.txt`; no other lane output is apparent on that path. Its optional `--junk` path invokes `junk-fixtures.py --run` with `--out-dir` telemetry and `--out` telemetry, but the fixture generator creates temporary fixture repos under its scratch root (not telemetry); these are scratch, not round data. Crucially, it only produces `junk-c.txt` and `junk-ca.txt` if explicitly called with `--junk <landing-rev>`; the script's default invocation never creates the junk receipt promised by either claim's `do_nothing_control`. It splits the aggregate receipt by `awk` into the named files. No dry-run mode exists; I walked the script rather than running it because it requires a freeze and writes telemetry.

   **Smallest correction:** make the freeze procedure explicitly invoke `run-controls.sh <freeze> <base> --junk <landing>` and require the resulting split files; or remove the claim of production by this script and name the separate required invocation. Do not treat the default control run as satisfying junk controls.

2. **Cheapest skip-work controls and expected red legs (based on claim leg contracts):**

   * C: copy the nine registry rows with stub/empty evidence/entries. ROWS may pass if row shape and exact fields are fabricated correctly; ENTRIES is explicitly only a length-and-shape gate, but requires >=478 body words plus provenance/section, so header-only stubs fail ENTRIES (also J1 fixture tests that case). Missing/mismatched page quote/evidence fails EVIDENCE (J2 tests quote removed with valid window digest); absent Gate admit/reject records fails GATE; missing/corrupt assimilation evidence can independently fail REPOINTED/REJECTS/GROUND/CITEDLINES/CENSUS/SCRATCHMIRROR/COLLCHECK as applicable. Merely adding the nine registry rows is therefore not sufficient. A higher-effort sham entry with 478+ generic words and shape-valid fake claims might pass ENTRIES: that leg does not establish semantic mined work. It still must satisfy citation, Gate, evidence, census, and cited-line legs; do not claim ENTRIES alone proves substantive scholarship.
   * C: add only README index rows (and even repair the heading/footer) while omitting entries/rows/evidence. INDEX can pass in isolation, but ENTRIES/ROWS/REPOINTED/GATE/EVIDENCE/REJECTS and associated provenance legs go red. The index is not an alternative data path.
   * Ca: rewrite just SHONEN current counts, without ledger correction rows and other repairs. REPAIR checks every frozen REPAIR pair's observed token at Ca lands and additionally validates the sweep/README/SKILL/QUALITY surfaces; incomplete counts make REPAIR red. ANNOTATE remains red without correction rows; APPENDONLY may be green, which is not enough for acceptance.
   * Ca: rewrite only the displayed correction tokens/reword prose, without valid re-derivation commands and actual corrections. ANNOTATE requires each pair's old/new token and re-derivation command and reruns it; NOSTUB catches placeholder/shape omission. REPAIR separately checks the corrected statement against re-observed bytes. Both are red for token-only text. A constant-print ledger is addressed by LEDGER's executable allowlist (J4f specifically mutates the freeze ledger); changing only graded-tree ledger bytes instead trips frozen-byte consistency, not the frozen LEDGER parser.

3. **`lands == freeze` has the intended failure semantics in the declared controls.** The C counter documentation explicitly says it grades equality with freeze (not a refusal), returning `ACCEPT-C-75: FAIL` with FROZENCFG green and data legs red; Ca claim text and counter implementation likewise say equality is graded, not refused, with FROZENCFG/LEDGER green and repair/annotation legs red. By contrast, equality to base is refused and prints FAIL. The claim-level Ca do-nothing sentence additionally says R1EXEMPT green because its G/R fixtures are present and rerun; this does not mean the ordinary script runs junk fixtures. The live control script itself was not executed (would write telemetry and needs real revisions).

4. **No seat-output parser issue identified.** Neither `accept-c.py` nor `accept-ca.py` reads/parses seat output as an input. The counters consume repository bytes, claims/ledger JSON, receipts, and rerun command output; Ca's receipt logic requires exact round-74 verdict stdout, not a seat's free-form/JSON-wrapped response. Thus the run-10 plain-vs-JSON-wrapped seat-output parser requirement does not apply to these counters. Any upstream harness that parses seat text is outside these counter sources and must own that compatibility check.

## Axes / disposition

- **Coverage (C):** risk is a shallow but long-shaped entry passing ENTRIES; controls cover header-only stubs and quote-removed evidence, not arbitrary semantically empty 478-word prose. Existing other legs still constrain the simple row-only and README-only bypasses.
- **Calibration (Ca):** ledger-recomputed repairs and correction annotation checks are specifically resistant to count-only and token-only edits; R1 exemption has independent green/red fixtures. Ordinary controls are incomplete until the optional junk invocation is run and its files are confirmed.
- **Smallest safe action:** enforce the `--junk <actual-landing>` invocation as a required freeze checklist step; retain the existing fixture suite; describe ENTRIES as structural/length only (as the claim already does), and do not overstate it as a content-quality guard. No counter or claim rewrite is justified by the evidence here.
