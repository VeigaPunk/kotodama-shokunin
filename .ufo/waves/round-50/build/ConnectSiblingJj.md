## What the fleet converges on (patterns transferable to O)

- **P1 — Three values, not two.** Every correct sibling separates (a) tree source, (b) on-branch/landed, (c) pushed. `source`/`head`/`pushed` in revpin (S5), `branch_tip`/`origin_tip` in `_revision.py` (S4), `commit`/`head_differs_from_branch` in pin-disposition (S8). None equates "HEAD" with "landed", and none equates "on local branch" with "pushed" (`souji-verify.sh:166-168`).
- **P2 — HEAD is compare-only.** Its divergence is reported as a fact (`head_equals_source`, `HEAD_BRANCH_MISMATCH`, `head_differs_from_branch`), never suppressed and never used as the cited identity.
- **P3 — Missing refs are absence of evidence, not failure.** `_revision.py:186-191` skips the origin leg when the ref is absent; revpin sets `remote: null, pushed: false`; mori only fails closed when the lane is *jj-colocated* and its mirror is invalid (`:844-880`). This is what keeps the base controls `unborn-receipt-allowed` (`receipt_guard.py:291`) and `untracked-receipt-allowed` (`:259`) intact.
- **P4 — Never `refs/jj/*`.** Keep refs are not roots (S1 `:222-223`, S3 `:44-58`, `souji/SKILL.md:112`), and `git log --all` overcounts because of them: 5 reported vs 1 real (`JjConnectorProvinces.md:102-103`).
- **P5 — Discriminating fixtures, not green fixtures.** S1's `base-vacuity` block fails the suite unless the pre-fix stub reproduces every refusal; S2 pins base-side red expectations at `:47`; S5's receipt stores baseline extracts and both red and green observations. A suite that only asserts the fixed behaviour can pass on the broken tool.
- **P6 — One implementation, independent judge.** `_revision.py` docstring (`:9-12`) keeps the judge (`check-revision-binding.py`) on its own copy so it does not grade the code it shares. Directly applicable to O's probe: it must read tool bytes and not import them.
- **P7 — Measure the CLI, not the source.** `souji-verify.sh` carries a shadowed earlier `try_pushed` (`:268-293`) under the effective one (`:704-746`); the fixture measures only through the CLI (`r17-jj-receipts.sh:14-15`). An O control that greps or imports functions would grade dead code.

## Contradictions and things not to copy

1. **Selftest green under colocation proves nothing here.** `JjTrialKotodama.md:93-95` ran all three lane selftests in a colocated clone: `receipt_guard` 45/45, `claims-freshness` 43/43+19/19, `check-readme-revisions` all pass, "identical — no colocation failure". The same tools still fail R1/R2/R3 when HEAD is anchored below the tip. The 45 controls do not contain the defect shape (ReviewGuardControls enumerates all 45; none builds a branch-ahead-of-HEAD fixture).
2. **"Landed ≠ HEAD" is the wrong invariant.** In the push-failed state, `refs/heads/main` equals HEAD and both are unpushed (`CriticOperability.md` E3); in the steady state HEAD equals `origin/main`. A fix that labels the branch tip "landed" unconditionally repeats R1 under a new label. S1/S4/S5 all make pushedness an *ancestry test against a remote ref*, not a comparison to HEAD.
3. **The prior wave's `--all` mitigation is falsified.** `JjConnectorProvinces.md:102-103,182` — `--all` includes `refs/jj/keep/*` and never yields SAFE. Do not use it for receipt roots or counts.
4. **A durable-root requirement is stronger than `cat-file -e`.** R3's recommended `cat-file -e` (JjAuditKotodama rec. 3) still accepts an object held only by a keep ref, which is exactly the object class jj can rewrite/abandon. S1's rule (durable reachability) is the fleet's answer, and it fails closed on the *right* predicate. No sibling uses plain existence as durability.
5. **No sibling probes a path on `origin/<branch>`.** `grep` for `ls-tree` against `refs/remotes/origin` in `kotodama/tools`, `souji/tools`, `tsukuroi/tools` returns nothing. R2's per-ref path probe has no precedent to copy; the closest structural analogue is mori's branch-anchored report-closure row (S7). Treat it as new code with its own controls, not as a port.

## One bounded proposal

Give claim O the fleet's **P1+P3+P5 shape** as a single control contract, rather than R1/R2/R3 as three independent patches:

1. Resolve three refs once (`HEAD`, `refs/heads/<branch>`, `refs/remotes/origin/<branch>`), each as an optional commit id — no ref ⇒ `null`, never an error (P3).
2. `receipt_guard` probes `ls-tree` on each resolved ref, in that order, and refuses on the first hit with a diagnostic naming the ref that carried it (`committed_sha` keeps its meaning as the tree source; a new `landed=<sha|none>` is printed **only** when the found ref is an ancestor of `origin/<branch>`; otherwise `landed=none`, P2). This keeps every one of the 45 existing controls valid because the fixture repo has neither `main` nor `origin` and all new refs resolve to `null`.
3. `check-readme-revisions` resolves `BASE_COMMIT` through durable reachability (heads|tags|remotes, never `refs/jj`) before `git show`, with `GIT_*` scrubbed, and exits 2 with a typed diagnostic when it is not durable — the `skip()` path at `:233,303-311` is deleted, not merely made louder.
4. The O probe gains S1's `base-vacuity` arm (base bytes must still score 3/3) and one new negative control per new refusal ref, so a guard that always refuses cannot score 0/3. The Ca fixture adopts the same rule for its known-inseparable pair.

## Risks

- **E7 coupling** (`CriticOperability.md` E7): current controls assert `committed_sha={head}` in stderr and the fixture HEAD is `refs/heads/control` with no `main`/`origin`. Adding `landed=` as an extra field is safe; redefining `committed_sha` or requiring `origin/main` to exist is not. Each new control must be proven to fail on base bytes.
- **Remote staleness:** `refs/remotes/origin/main` is last-fetched state (`kaidoku/SKILL.md:580`). Label it as such; do not claim it certifies the live remote.
- **Durability coupling:** requiring durable reachability for `c42d675` passes today (`CriticOperability.md` E4: reachable from `refs/heads/main`, repo not shallow) but makes the selftest depend on the clone's refs. That is the intended fail-closed tradeoff and belongs in the tool's docstring, not in a silent fallback.
- **Scale:** per-ref `ls-tree` is three cheap tree walks; no sibling evidence suggests a timeout risk at this file count.
