# R22-D03 — family-clean projection rule

Date: 2026-10-18. Status: design for the R22-D04–D06 implementation owner; not an implementation or gate-pass receipt. Basis: `reports/round-22/bleed/analysis.md` (R22-D01–D02); baseline revision `46a03257ee75dd8f685a105e47da3f45a0154172`. All source line references below are at that revision.

## Decision: family-clean, not borrowed-reference relabeling

Use the packet family's own labels and rank records. For D4, do **not** carry the embedded D2 normalization ledger, even under a new field name: D4's brief bans importing that system (`examples/culture-d4/components/01-brief.yml:55-75,111-121`), and the delivered D4 packet already has its own rank rules. Preserve the D2 path and its serialized projection byte-for-byte. No garment form is filled, no D2 debt is resolved, and no canon/rights decision is made by this change.

A generated owned record is family-clean when its text, record identity, source field/component, owner, scheme, rank references, and findings are grounded in the current family's packet or its declared components. A D2 rule or D2 garment reference cannot become D4-owned merely because its unqualified ID or era tag also exists in D4. Identity is at least `(family, source block/component, record id)`, not just `GAR-01`, `WR-01`, or `E0`.

Reusable machinery is not borrowed culture data. The tool path `tools/d2-typed-labels.py`, shared `D2L-*` diagnostic vocabulary, historical schema/method references, and a sentence explaining that a foreign component was **not** read may remain. They are not D4 record citations. Check owned fields structurally; a whole-document ban on the substring `D2` would reject legitimate method provenance and D4's explicit contrast declarations. D4's orthography component itself has `WR-*` writing-rule IDs (`03-orthography.yml:83-90`), so a naked `WR-*` token denylist is also unsound.

## Source-level change contract

1. Resolve the packet family **before** choosing the rank ledger in `run_pipeline` (baseline `tools/d2-typed-labels.py:2585-2637`). Keep the existing `build_payload()` and D2-only constants behind the D2 branch. A D4 run must not invoke D2's `build_payload`, `project_to_gate`, rank-token interpretation, entitlement/conflict triage, or quarantine/residual tables. The round-20 family-local alias leg is retained; it is not evidence that the independent rank leg is local.
2. Build D4's rank view from `packet.rank_rules`: the packet-native gate-shaped `RK-01..RK-04` rows, not D2's prose fixture. Preserve the declared authority, jurisdiction, effective eras, rites, effect, property kind/value and wearer/exempt ranks. Their source must name the D4 packet's `rank_rules` block and/or `examples/culture-d4/components/09-costumes.yml:133-137`, with the exact source record ID. Missing fields must stay missing/explicitly unsupported; do not manufacture D2 enforcement, assays, garment links, rank tokens, or exceptions. These rows are already gate-shaped; do not send D4 values through D2's `GATE_VALUE_MAP` or its prohibition/license inversion.
3. Preserve the consumer-facing ledger keys (`normalized_rules`, `gate_rank_rules`, `act_rules`, `residuals`, `unresolved`, `quarantine`, `calibration_flags`, `entitlement_edges`, `jurisdiction_gaps`, `assay_gaps`, `coverage`) so existing readers can distinguish empty/not-applicable arrays from missing schema. Populate the first two from the D4 packet-native rank view, using a minimal declared shape conversion where needed. Derived `#g` IDs must map back to the same RK source ID. D2-only arrays are empty for this D4 fixture; they must not be copied or populated from globals. Do not call an absent/unsupported leg evaluated: report an explicit family-local skip or limitation instead of making up a rule. A malformed declared rank row is a stable shape failure, never silently discarded.
4. Generate label provenance with family-aware metadata while keeping D2 defaults unchanged for existing direct helper calls and controls (`project_labels`, `parse_typed_labels`, and the constructors at baseline lines 493-637). D4's garment and owed-slot owner is `09-costumes`; lexicon owner is `04-lexicon`; name owner is `05-naming`. Source components must name those actual D4 owners (or the D4 packet plus the precise block), not D2's `11-costumes`, `05-lexicon`, or `13-naming`. For supplied native/borrowed forms, use the packet's declared `orthography.scheme`, `D4-roman-1 (lowercase ASCII; length as double vowels; diphthongs ai/au; no diacritics)`, rather than inventing `d4-roman` or retaining `d2-roman`. Translated/gloss and unfilled slots keep their existing null scheme and issue reasons. Preserve all texts, kind assignments, borrow ledgers, record IDs, and owed-slot links. If owner names change, preserve the parser's requirement that costume labels have a slot ID; its baseline `owner == '11-costumes'` check at line 763 must not become a loophole. Explicit hand-authored typed-label rows must be checked for foreign owned provenance, not silently scrubbed or rewritten.
5. Make projection `name`/`canon` describe D4, while retaining non-canon status and the actual generator path. Compute coverage and findings from the selected family view. Flatten only that view's conflicts into `findings`: inherited D2 conflict rows cannot survive indirectly in the typed adapter after their cited ledger is removed. `assembly.packet` and its digest remain bound to the actual D4 packet.

Unknown families may retain an explicitly documented compatibility behavior, but must not silently receive a D2 rank fixture under another family's owned fields. Prefer the existing per-family alias principle: packet-local declarations, an explicit skip if a leg is undeclared, and fail-closed handling of malformed declarations.

## Expected D4 delta, not yet a measured post-fix result

- Same 74 labels (56 native-form / 12 translated-label / 6 borrowed-strata), same 68 supplied/gloss texts and six null owed-form labels; six owned garment terms remain unfilled, represented by twelve label holds.
- Rank coverage changes from the D2 fixture's 21 component / 9 normalized / 5 gate-projected rows to D4's four declared RK rules, each preserved once in the local normalized view and gate view when that view uses an explicit lossless gate-native mapping. A skipped adaptation must be labeled as skipped, never counted as evaluated.
- With the lossless four-rule view, the fixture has no D4 act-rule, residual, quarantine, entitlement, jurisdiction-gap or assay-gap rows to emit. The D2-derived 13 unresolved items, three quarantine handles, four conflicts, three rank holds and one rank note disappear **from D4 ownership only**; the D2 projection keeps them unchanged.
- Expected D4 findings become 12 form holds, zero rank findings, zero notes and zero fails. This is removal of misattributed D2 findings, not resolution of D2 rank defects or the six owed garment forms. The existing +9/+1 historical reconciliation remains historical evidence, not an expectation to preserve by manufacturing replacement D4 holds.

## Required paired controls

Implement controls in the existing selftest surfaces, not a new test framework. Each positive must be paired with a defect that would defeat a merely cosmetic fix:

- **D2 compatibility:** baseline D2 serialized projection remains exactly `a3aa452cd5ae77c351d9532a707fb1f1ababf77c3fad8b9d28089e6958364a43` (baseline artifact); D2 `--check` and embedded selftests pass. A D2 rank mutation in an isolated control must still affect D2, proving that compatibility is not achieved by disabling rank projection globally.
- **D4 independence:** D4 packet-only mirror builds byte-identically without a D2 examples tree **and** no D2 normalized rule, act, residual, quarantine citation, or foreign owner/scheme survives in D4-owned fields. Poison the embedded D2 constants or replace `build_payload` with a raising sentinel for a D4 helper probe: D4 output must remain identical. The pre-fix helper control C3 proves why filesystem absence alone is insufficient.
- **Not empty-by-default:** mutate RK-01's declared authority/property/rank in an isolated D4 packet and assert only the corresponding D4 rank projection changes. Add/remove one valid RK row and coverage must change exactly once; malformed or duplicate declared records must fail rather than quietly vanish. This defeats a fix that simply replaces the D2 ledger with empty arrays.
- **Owner-qualified citations:** inject an absolute D2 rank citation, a short `12-rank-rules.yml` citation, or a foreign owner/scheme into a D4-owned label/rank field; the boundary control must reject it. The untouched baseline D4 projection must fail this semantic rule even though it was deterministic. Genuine D4 `WR-*` orthography IDs and reusable tool/schema references remain allowed in their proper contexts.
- **No ID-based reinterpretation:** D4 GAR-01/GAR-06 must retain their D4 ranks/text, never D2 `RANK_RESOLUTIONS`; ordinary canonical E-tags must not import D2 eras. A same-ID foreign-record probe must fail ownership checks, while the six local owed-slot IDs still route to their six garments.
- **Honest borrowed language:** the six existing `borrowed-strata` labels retain their packet-declared donors, layer refs and adaptation rules. This linguistic borrowing is not a license to import D2 fixtures. An undeclared/foreign donor citation in an owned source field must not be legalized by relabeling the whole ledger as borrowed.
- **Propagation/tamper:** stale projection pin, stale expected-hold set, or one changed typed routing byte must fail the existing gate/adapter checks. A clean regeneration must pass, proving that the profile/pins were genuinely updated rather than bypassed.

## Draft rule for the orchestrator's SKILL.md integration

> A multi-family projector selects data and provenance by the input packet's family before constructing labels, rank ledgers, coverage, or findings. Shared parser/gate code and diagnostic names may be reused; another family's fixture records, bare-component citations, owner labels, romanization schemes, residuals, or conflict findings may not appear in family-owned fields. Preserve explicit linguistic borrow ledgers without treating them as permission to borrow fixture data. Pair same-family source/ID/field checks with both a D2-constant poison control and a local-packet mutation control: a foreign-tree-free rebuild proves dependency isolation, not data isolation. Keep historical packets and frozen expectations immutable; record changed semantics, debt removal, and pins in new, dated rows with controls.
