## 1. What the re-pin is (design §5 rows P1, P2, P8)

The round-11 frozen generation pins the typed pipeline: row 1 of
`tools/gates/frozen/round-11/MANIFEST.tsv` records gate
`typed-pipeline-gate.py d102fd1d…` over the frozen typed packet `1b5010b7…`,
producing exit 0, 15 `FINDING` lines and stdout bytes `9a69985a…`.

`tools/replay-frozen.py` verifies a row's `gate_sha256` **before** launching, so
after the round-18 gate generalization that filed row can only read
`gate_digest_mismatch` (could-not-evaluate). The row cannot be "fixed" in place:
editing it would make one filed file the record of two gate revisions, which the
append-only rule forbids. The re-pin is therefore a **new generation** (design
§5 P1/P2) plus the recorded class of the superseded row (P8):

```text

    packet.d2.typed.yml         byte copy of the frozen typed packet
    packet.d2.yml               byte copy of the frozen legacy packet

```

Peer workers were editing the gate throughout this seat's window; the shas this
seat measured were, in order:

The stable part is the verdict, measured at each revision this seat pinned:
under `ea95e2a1…`, `286d6e82…` and `d96958b6…` the re-pin reproduced **exit 0,
15 `FINDING` lines and stdout `9a69985a…` byte-identical to the filed round-11
`run.log`**, and the D2 regression controls read the same values each time
(default `15cdfbda…` exit 0, `--json` `19765ddf…` exit 0, selftest 12/12 —
R18-O11's receipts, `reports/round-18/gate/tests-1.md`). The moving part is the
digest cell, which is why this section ends in a one-command refresh.

At the freeze revision the controls were re-read (10:50Z): default path
`15cdfbda…`/exit 0 (16/16 legs), `--json` `19765ddf…`/exit 0, frozen packet
`9a69985a…`/exit 0, selftest 12/12 — all byte-equal to the pre-change readings.

Consequences, stated without spin:

- The row pins `d96958b6…`. If the gate settles on a later revision, the row
  reads `could-not-evaluate` again — the same supersession class as P8 — until
  the gate cell is re-pointed. That is a one-value substitution in **this seat's
  own new file** (the filed round-11 generation is never touched); the command is
  in `table.md` §5, or `.scratch/o07/build-repin-d2.py --build` re-derives it from
  the filed manifest and re-verifies.
- **One home, and the runner discovers it.** The generation lives only at the
  design's path; the seat removed an earlier byte-identical copy under
  `reports/round-18/repin/`. The runner's globs (`run-validation.py:137-145`)
  discover both `tools/gates/frozen/round-18*/MANIFEST.tsv` and
  `tools/gates/frozen/round-18*/**/MANIFEST.tsv`, and it requires **every**
  discovered manifest to replay green (`run-validation.py:884-893`). So this
  manifest is a measured leg of the counting command — currently
  **11/11 reproduced, exit 0** (10:48Z) — and it is also the one leg that goes
  red if the gate revision moves before integration. The D4 seat measured the
  same exposure and dropped its copy of a gate-pinned row
  (`reports/round-18/d4/manifest.md` §4); here the leg is wanted, so the answer
  is the documented re-pin, not removal. The runner's own frozen-row leg also
  re-runs the gate over the round-11 typed packet and compares stdout to
  `9a69985a…` (`d2_path.frozen-row.stdout_identical: true`).
- The re-pin is safe to repeat: the recorded exit (0), finding count (15), output
  bytes (`9a69985a…`) and the other ten rows are byte-equal by construction, and
  a later revision that changed the D2 verdict would surface as a replay
  *mismatch* instead of a digest mismatch — the control is in the replay, not in
  this prose.
- A gate revision may also be pinned only at its live path: `tools/replay-frozen.py`
  refuses any gate that is not exactly `tools/gates/<name>.py`
  (`replay-frozen.py:133`), so a frozen copy of the gate inside the generation
  cannot make the pin self-contained. That is a property of the standard, not a
  gap this seat can close.

## 9. Limits

- The re-pin pins **the digest**, not the design: it proves the frozen packet
  under the pinned revision produced the recorded verdict. It is not a claim that
  the generalization is correct, complete, or that D4 is gated — that is the
  claim-D work.
- The frozen row stays red at the design level: exit 0 with 15 open hold lines
  means the emitted findings equal the frozen expected hold set, nothing more.
- Freshness is bounded by the wave, not by this seat: the pin is as good as the
  revision it names. The re-pin command is one cell; the verification is one
  replay; both are in §7 and §8 so a later integration can repeat them without
  this seat's scratch files.
