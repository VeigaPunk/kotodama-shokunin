## Metadata-shard allocation discrepancy

The Round-8 target in `reports/round-8/targets.json` declares six civilization ranges: 01–16, 17–32, 33–48, 49–64, 65–80, and 81–94. I compared that declaration with the actual civilization-fragment headers using this read-only command on 2026-10-17:

```sh
export TMPDIR=$PWD/.scratch
python3 - <<'PY'
import json
from pathlib import Path
spec = json.loads(Path('reports/round-8/targets.json').read_text())['metadata_sweep']
fragments = sorted(Path('reports/round-8/metadata').glob('m*-civ-*.md'))
print('declared:', spec)
print('observed civilization metadata fragments:', len(fragments))
for path in fragments:
    print(f'{path}: {path.read_text().splitlines()[0]}')
PY
```

The command found five actual fragment ranges: M01 1–19, M02 20–38, M03 39–57, M04 58–76, and M05 77–94. Those ranges are contiguous and cover 94 civilization files, but the dispatch ranges and shard count do not match the target. **Disposition: defect in the Round-8 target/dispatch accounting**; this is an allocation-record mismatch, not a missing corpus entry. The filed Round-8 artifacts are unchanged.
