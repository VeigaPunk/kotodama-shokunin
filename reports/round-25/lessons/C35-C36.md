## 2. What the C31 tool does not check (the reason a final pass exists)

The tool's four claims are row/file set equality (C31), owner resolution
(C32), documented formats (C33) and pin re-derivation (C34). It therefore
cannot see:

1. **A disposition pointer that names a nonexistent path.** Its `resolves()`
   function is applied to the **queue owner column** only; §2's disposition
   pointers are prose the tool never resolves.
2. **Evidence that is not a `*.md` lesson file.** Its census globs
   `corpus/lessons/*.md`; the nine subdirectories are invisible to it.
3. **Whether a *green* is green on the current bytes** — it does check pins,
   which is exactly why C35-3 surfaced as `FAIL C34_pins_rederived` after the
   X38 survey appended to `round-25.md`.

So the tool's `findings: 0` is a necessary but not sufficient condition for the
index's correctness, and this fragment names the gap rather than implying the
green covers it.

## 5. Lessons entry — what this round's C work teaches

1. **A checker's green defines its own blind spot, and the blind spot is where
   a final pass earns its seat.** The C31 tool passed its four claims while the
   README carried a pointer to a directory that does not exist and left 146
   files undocumented. Both are correctness defects in the same artifact the
   green describes. The rule: before treating a checker as the acceptance
   instrument, enumerate what it does **not** read — here, prose columns and
   non-`*.md` paths.
2. **A relative name in a filed lesson is not a repo-relative path.** The
   round-4 lesson says "17 audit reports under round-4-audit/"; the index
   resolved that to `reports/round-4-audit`, which has never existed. The
   correct base was found by cross-reading the corpus: ten
   `corpus/knowledge/linguistics/` headers cite the **full** path
   `corpus/lessons/round-4-audit/linguistics.md`. A resolver that only tried
   one base would have called the pointer a fabricated citation.
3. **An index that pins live bytes must be re-pinned when a peer appends; the
   pin is not a claim, it is a measurement.** `round-25.md` moved twice under
   the round's own seats. The row's *existence* and its *pin* are different
   kinds of fact: the row is history (a lesson landed), the pin is a
   present-tense reading. Conflating them produces either a stale cell or a
   wrongly "corrected" history.
4. **A filed count that disagrees with the live tree is recorded, not
   repaired.** The round-4 "17 vs 16" delta is named in the revision block and
   left in the filed bytes. Editing the lesson to match the directory would
   destroy the evidence that the round-4 tally was taken under a different
   census — the same discipline the round-17 and round-22 lessons state for
   their own filed numbers.
5. **Write only into a settled file.** The README was sampled for stability
   (five reads over 150 seconds) before any edit. The sibling C seat's own
   finding (C-2) records the cost of the alternative: a queue whose prose lagged
   its table inside a single instant.
6. **The index is a pointer, not a verdict — and its own revision block must
   say so.** Revision 2 names the three edits, the control that re-verified
   them, and the boundary. Revision 1's rows stand unedited, per the file's
   closing rule.
